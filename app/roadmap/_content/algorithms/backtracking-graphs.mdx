## Backtracking

Backtracking is an algorithmic technique that considers searching through all possible configurations to find a solution. It aggressively **prunes** dead ends to avoid unnecessary computation.

## The Recursive Pattern

1.  **Choose:** Add a candidate to the current path.
2.  **Explore:** Recurse deeper with the updated path.
3.  **Backtrack:** Remove the candidate (undo the choice) and try the next one.


| Problem Type | Goal | Complexity |
| --- | --- | --- |
| **Subsets** | All possible groups | O(2^N) |
| **Permutations** | All possible orderings | O(N!) |
| **Combinations** | Groups of size K | O(N! / (K!(N-K)!)) |



> [!tip] Pruning is Key
> Backtracking is slow by nature. To pass strict time limits, you must **prune** the search tree by adding `if` statements that stop recursion as soon as a path is guaranteed to fail.

## Graphs & Union Find

Graphs represent relationships between entities using nodes (vertices) and edges. They are the backbone of social networks, maps, and dependency management.

### Traversal Strategies

- **Breadth-First Search (BFS):** Uses a **Queue**. Ideal for finding the shortest path in unweighted graphs or processing level-by-level.
- **Depth-First Search (DFS):** Uses a **Stack** or recursion. Ideal for exhaustive searches (finding all paths) and counting connected components (Islands).
- **Union Find:** An advanced data structure used to group connected components and detect cycles in an undirected graph in near **O(1)** time.


| Algorithm | Best For | Typical Complexity |
| --- | --- | --- |
| **BFS** | Shortest Path | O(V + E) |
| **DFS** | Island Counting | O(V + E) |
| **Kahn's (Topological)** | Course Scheduling | O(V + E) |



> [!info] Adjacency List vs Matrix
> In most LeetCode problems, an **Adjacency List** is more efficient for sparse graphs. Use an **Adjacency Matrix** only if the graph is very dense or the grid is fixed.

## Advanced Graphs (Shortest Path)

Advanced graphs deal with weighted edges where simple BFS isn't enough to find the cheapest route.

## Optimization Algorithms

- **Dijkstra's Algorithm:** Uses a **Min-Priority Queue** to find the shortest path in graphs with positive weights.
- **Bellman-Ford:** Capable of finding shortest paths even with **Negative Edge Weights** and detecting negative cycles.
- **Minimum Spanning Tree (MST):** Algorithms like **Kruskal's** or **Prim's** connect all nodes with the minimal total edge cost.


> [!warning] Negative Weights
> Dijkstra will likely fail if the graph has negative edge weights. In that scenario, use Bellman-Ford, but be aware it is slower (**O(V * E)** vs Dijkstra's **O(E log V)**).



> [!ai] Union Find + Kruskal's
> Kruskal's algorithm heavily relies on **Union Find** to check if adding an edge will create a cycle in the spanning tree.
