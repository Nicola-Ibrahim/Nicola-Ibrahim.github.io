# Linear Data Structures

## Linked Lists

Linked lists test your ability to manage references and memory pointers without losing data. Unlike arrays, they don't have contiguous memory, making "indexing" an **O(N)** operation.


| Operation | Complexity | Note |
| --- | --- | --- |
| **Prepend** | O(1) | Just update the head pointer. |
| **Append** | O(N) | Requires traversing to the end. |
| **Search** | O(N) | No random access. |


### Pro Techniques

- **Dummy Nodes:** An essential trick where you create a "fake" head node. This simplifies edge cases like deleting the first node or merging lists.
- **Tortoise and Hare:** Using a `fast` (2x) and `slow` (1x) pointer to detect cycles or find the middle element in a single pass.
- **In-Place Reversal:** Carefully swapping `.next` pointers without allocating new memory.


> [!tip] Linked List vs Array
> Use **Linked Lists** when you need frequent insertions and deletions at the ends. Use **Arrays** when you need frequent random access by index.

## Stacks & Queues

Stacks and Queues are restricted access structures that provide deterministic order for processing data.

## The Two Models


| Structure | Logic | Analogy |
| --- | --- | --- |
| **Stack** | **LIFO** (Last In, First Out) | A stack of clean plates. |
| **Queue** | **FIFO** (First In, First Out) | A line at the grocery store. |


## Advanced Patterns

- **Monotonic Stacks:** A stack that maintains strictly increasing or decreasing elements. This is the gold standard for solving "Next Greater Element" problems in **O(N)** instead of O(N²).
- **Queues in BFS:** Queues are the backbone of Breadth-First Search, used to process graph nodes level by level.


> [!warning] Stack Overflow
> When using recursion, the computer uses an internal **Call Stack**. If your recursion is too deep (e.g., infinite loop), you'll trigger a Stack Overflow error.
