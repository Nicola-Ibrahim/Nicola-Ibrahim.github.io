## Dynamic Programming (1D & 2D)

Dynamic Programming (DP) is an optimization over plain recursion. If you see recursive calls with the same parameters being made multiple times, you should use DP to cache the results.

### Two Approaches


| Approach | Strategy | Pros | Cons |
| --- | --- | --- | --- |
| **Memoization** | Top-Down (Recursive) | Easier to implement | Stack overflow risk |
| **Tabulation** | Bottom-Up (Iterative) | No recursion overhead | Harder to visualize |


### When to use DP?

- **Overlapping Subproblems:** The same sub-calculations are performed repeatedly.
- **Optimal Substructure:** The optimal solution to the problem can be built from optimal solutions of its subproblems.
- **Common Keywords:** "Maximum", "Minimum", "Number of ways", "Longest".


> [!tip] Space Optimization
> Many DP problems (like House Robber) only require the last two results. Instead of an array of size **O(N)**, you can use two variables to achieve **O(1) Space**.

## Greedy Algorithms & Intervals

Greedy algorithms make the best possible choice at the current moment without worrying about the future. While simpler than DP, they only work if the "local optimum" leads to the **Global Optimum**.

## Interval Patterns

Interval problems are almost always solved by **Sorting** first.


| Goal | Sort By | Strategy |
| --- | --- | --- |
| **Merge Overlaps** | Start Time | Merge if `current.start < last.end` |
| **Max Non-overlapping** | End Time | Take the one that ends earliest |
| **Meeting Rooms** | Start Time | Use a Min-Heap for end times |


## Key Greedy Concepts

- **Greedy Choice Property:** A global optimum can be reached by making a local optimum choice.
- **Optimal Substructure:** An optimal solution to the problem contains an optimal solution to subproblems (shared with DP).
- **Proving Greedy:** Usually involves a "Proof by Contradiction" or "Exchange Argument."


> [!warning] Greedy Trap
> Greedy does NOT work for the "Coin Change" problem in general (e.g., coins [1, 3, 4] for total 6). Greedy takes `4, 1, 1` (3 coins), but the optimum is `3, 3` (2 coins). This is why Coin Change is a classic **DP** problem.



> [!info] Kadane's Algorithm
> The "Maximum Subarray" problem uses a greedy approach (Kadane's) to decide whether to start a new subarray or continue the current one in **O(N)** time.
