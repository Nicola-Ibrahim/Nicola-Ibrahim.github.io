## docs-knowledge-overview

Documentation is often the first thing to go stale in a fast-moving project. By treating documentation as a **Task** for an AI agent, you ensure that your READMEs, diagrams, and API specs are always in sync with the actual code.


| Skill | Focus | Output Format |
| --- | --- | --- |
| **Arch Mapper** | System Visualization | Mermaid Diagrams |
| **Docs Generator** | API & READMEs | Markdown / OpenAPI |



> [!info] The 'Living' Codebase
> When your agent understands your architecture and can document it on the fly, your codebase becomes its own documentation. This eliminates the "knowledge silo" problem in engineering teams.







## Architecture Mapper

Keeps the "big picture" of your software clear by automatically mapping dependencies and component roles as the system evolves.

## 🗺️ Visualizing the System

- **Dependency Mapping:** Visualizes how different modules interact using Mermaid flow diagrams.
- **Component Auditing:** Generates a high-level inventory of responsibilities for each directory.
- **Onboarding Speed:** Dramatically reduces the time needed for new developers (and AI agents) to understand the project structure.


> [!tip] Mermaid Integration
> Use this skill to generate a `DIAGRAM.md` file in every major module. Most modern editors (and GitHub) render Mermaid natively, providing instant visual clarity.



```prompt
Create an Architecture Mapper skill. Set up the directory .agent/skills/architecture-mapper/ with standard subfolders.
In SKILL.md, add name: architecture-mapper and description: Trigger this when I ask to 'Explain how the system fits together' or 'Map out the project structure'.
Instruct the agent to look for key files (index.ts, main.py, etc.) and generate a high-level Markdown list of component responsibilities. It must identify external dependencies and show how they are imported. Create a template in resources/arch_diagram.mermaid for the agent to follow when generating Mermaid flowcharts.

```






## Docs Generator

Teaches the AI to read source code routes and output structured markdown documentation that follows industry standards.

- **Auto-Updating:** Keeps READMEs and inline comments perfectly in sync with codebase changes.
- **API Formatting:** Formats documentation strictly to standards like **OpenAPI** or **Swagger**.
- **Template Discipline:** Follows an example route documentation template to ensure consistency across the entire API surface.


> [!ai] In-Code documentation
> Configure your Docs Generator to also write JSDoc or Docstrings while it builds features. This ensures the "Knowledge" stays as close to the code as possible.



```prompt
Create a Docs Generator skill. Set up the directory .agent/skills/docs-generator/ with standard subfolders.
In SKILL.md, add name: docs-generator and description: Trigger this when I ask you to update the README, generate API documentation, or write inline comments.
Instruct the agent to read the source code and generate clear, markdown-formatted documentation. For APIs, it should format outputs to match [Insert Standard, e.g., OpenAPI/Swagger]. Create an example in examples/api_endpoint_doc.md showing how a standard route should be documented.

```
