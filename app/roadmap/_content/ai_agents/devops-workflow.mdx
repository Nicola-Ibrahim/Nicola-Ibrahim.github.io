## Workflow Overview

DevOps is where AI agents truly shine. By automating repetitive tasks like migration verification, deployment health checks, and git hygiene, you free up your human engineers for deep architectural work.


| Skill | Focus | Safety Mechanism |
| --- | --- | --- |
| **Database Migrator** | Schema Changes | Forced Dry-Runs & Rollbacks |
| **Deployment Mgr** | Production Gates | Mandatory Health Checks |
| **Git Manager** | Version Control | Conventional Commit Enforcement |



> [!info] The Safety Gate Principle
> In an AI-driven DevOps workflow, the agent doesn't just "do" the work—it **proves** the work is safe before proceeding. This "gatekeeper" mindset is what prevents automated disasters.






## Database Migrator

Ensures your database stays healthy and synchronized by automating the lifecycle of migrations with built-in safety checks.

### Guided Migrations

- **Safety First:** Mandates dry-runs and rollback plans for every schema change.
- **Framework Aware:** Adheres directly to your tech stack (Prisma, Alembic, etc.).
- **Consistent Schemas:** Automatically verifies that migrations match the desired application state.


> [!warning] Data Integrity
> Never let an agent run a migration directly on production without human approval. The agent's job is to **prepare** the migration and **verify** it in a staging environment.



```prompt
Create a Database Migrator skill. Set up the directory .agent/skills/database-migrator/ with standard subfolders.
In SKILL.md, add name: database-migrator and description: Use this whenever the code change involves database schemas, migrations, or seed data.
Instruct the agent to always run 'dry-runs' first and to generate a 'Rollback Plan' before suggesting any schema changes. It must follow the repository's migration framework (e.g., Prisma, Alembic, Sequelize). Create a resource in resources/migration-checklist.md for the agent to follow.

```






## Deployment Manager

Reduces deployment anxiety by providing AI-driven gates for production readiness and automated post-deployment verification.

- **Vulnerability Checks:** Verifies secrets and environment variables before push.
- **Automated Health Checks:** Confirms the service is actually "up" via custom ping scripts.
- **Instant Release Notes:** Generates human-readable progress reports directly from git logs.


> [!tip] Staging Verification
> Configure your Deployment Manager to automatically run a suite of "smoke tests" against your staging environment before it even asks you to promote to production.



```prompt
Create a Deployment Manager skill. Set up the directory .agent/skills/deployment-manager/ with standard subfolders.
In SKILL.md, add name: deployment-manager and description: Trigger this before deploying to staging or production. It will verify all environment variables and run a health-check script.
Instruct the agent to look for 'Deployment Blockers' (e.g., failed tests, missing secrets). It must generate a 'Release Note' automatically from the commit history. Create a script in scripts/health_check.sh that pings your staging URL and checks for a 200 OK.

```






## Git Manager

Teaches the AI to read git diffs safely and generate highly consistent, professional workflow messaging for the entire team.

### Version Control Hygiene

- **Conventional Commits:** Enforces strict `feat:`, `fix:`, `chore:` formatting for a clean history.
- **Safe Diffing:** Uses scripts to safely extract codebase changes without risking side effects.
- **Rich Summaries:** Auto-fills "What Changed" and "How to Test" PR markdown templates.


> [!ai] Context is King
> The Git Manager skill is more than just a parser; it uses the LLM's understanding of intent to summarize *why* a change was made, not just *what* lines changed.



```prompt
Create a Git Manager skill. Set up the directory .agent/skills/git-manager/ with standard subfolders.
In SKILL.md, add name: git-manager and description: Trigger this when I ask to write a commit message, document a git diff, or write a Pull Request summary.
Instruct the agent to use Conventional Commits (feat:, fix:, chore:, etc.). Create a script in scripts/get_diff.sh that safely runs git diff. In examples/pr_template.md, provide the exact Markdown template the agent should fill out when summarizing code changes (including What Changed and How to Test sections).

```
