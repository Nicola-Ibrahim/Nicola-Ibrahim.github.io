---
title: "1. Modular Monolith"
shortDesc: "A single deployable unit divided into strict, isolated business modules."
---

A software architecture that keeps all code in a single deployable application but enforces strict internal boundaries.

**The Concept**

- **Single Deployment:** Everything runs in one process. You deploy one artifact. It is significantly easier to build, test, and release.
- **Strict Boundaries:** Code is organized by business domain (e.g., Billing, Users). Modules cannot directly access each other's databases; they must communicate through strictly defined internal APIs or interfaces.

**Why it's popular**

- **Simplicity:** Easier to debug and test than microservices. There is no network latency between modules because communication is strictly in-memory.
- **Future-Proofing:** Because the boundaries are already strict, it is incredibly easy to break a module out into a separate microservice later if it requires independent scaling.
