<Topic 
  id="sync-vs-async" 
  title="1. Sync vs Async vs Parallelism" 
  shortDesc="Understanding execution models: Blocking, Concurrency, and CPU-bound math."
>
Understanding the difference between blocking, concurrent, and parallel execution is crucial for backend performance. When developers say "just make it async", they are usually conflating three entirely different architectural concepts: I/O Concurrency, True Parallelism, and Event Notification.

**1. Synchronous (Sync): "Blocking"**
By default, Python is synchronous. It executes code exactly one line at a time.

**2. Asynchronous (Async): "Smart Waiting"**
Asynchronous programming is about dealing with multiple things at once by never wasting time waiting. Best for **I/O Bound** tasks (databases, API calls).

**3. Parallelism: "Brute Force"**
Parallelism is doing multiple things at the exact same physical millisecond, requiring multiple CPU cores. Best for **CPU Bound** tasks.

The magic of asynchronous programming is that the computer never waits. 

When a coroutine hits an `await` statement (like querying a database), it explicitly **yields control** back to the Event Loop, saying: *"I am going to sleep until the database answers. Go run something else!"*

<Topic 
  id="message-queue" 
  title="3. The Queue (1-to-1 Task List)" 
  shortDesc="A Point-to-Point communication pattern for executing specific background commands once."
>
A Queue represents a Point-to-Point communication pattern for executing specific background commands.

- **🧠 The Mindset:** "I need someone to do this specific job once."
- **🎯 Use Case:** Heavy tasks like image processing or inverse modeling.
- **🚀 Scaling:** You can add as many workers as you want, but each message is processed exactly once.
</Topic>

<Topic 
  id="pub-sub-event-bus" 
  title="4. Pub/Sub & The Event Bus (1-to-Many)" 
  shortDesc="The Publish/Subscribe paradigm for broadcasting facts to multiple independent listeners."
>
Pub/Sub (Publish/Subscribe) is an asynchronous communication paradigm where senders do not target specific receivers.

- **🧠 The Mindset:** "I am announcing a fact. I don't care who is listening."
- **🎯 Use Case:** Real-time dashboards, user notifications, or cross-service updates.
- **🚀 Decoupling:** Producers never need to know about Consumers.
</Topic>

<Topic

  title="5. The Message Broker (Infrastructure)" 
  shortDesc="The physical software engine that hosts your Queues and Event Buses."
>
The physical software engine (RabbitMQ, Kafka, Redis) that hosts your Queues and Event Buses.

- **🏛️ The Golden Rule:** Queues are for **Commands** (Do this action once). Event Buses are for **Events** (This fact happened, react to it).
