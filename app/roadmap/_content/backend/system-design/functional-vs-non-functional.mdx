---
title: "1. Functional vs Non-Functional Requirements"
shortDesc: "The difference between what a system does (features) and how it performs (architecture)."
---

Understanding the difference between Functional and Non-Functional requirements is the absolute foundation of System Design.

**1. Functional Requirements (The \"What\")**

These define what the system *must do*. They are the specific behaviors, features, and business rules that the application needs to execute.

- **The Focus:** Features, business logic, user interactions, and APIs.
- **Examples:** \"The user must be able to add an item to the shopping cart.\" / \"The system must generate a PDF invoice after a successful payment.\"
- **The Impact:** If you miss a functional requirement, the software simply doesn't do its job.

**2. Non-Functional Requirements (The \"How\")**

These define how the system *must perform*. Also known as \"Quality Attributes\" (the \"ilities\": scalability, reliability, availability, latency).

- **The Focus:** Performance, security, capacity, latency, and availability.
- **Examples:** \"The shopping cart page must load in under 200ms.\" / \"The payment system must be highly available (99.99% uptime).\"
- **The Impact:** If you miss a non-functional requirement, the software works for 10 users, but crashes and burns when 10,000 users log in.

**The Architectural Difference**

- **Functional** requirements dictate your *code* (e.g., writing a new Python function or SQL query).
- **Non-Functional** requirements dictate your *architecture* (e.g., adding Redis for caching, a Load Balancer for scale, or Read Replicas for database speed).
