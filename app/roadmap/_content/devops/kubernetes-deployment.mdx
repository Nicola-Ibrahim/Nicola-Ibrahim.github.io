<Topic 
  id="oidc-auth" 
  title="1. OIDC Authentication" 
  shortDesc="Connecting to AWS/GCP without long-lived passwords."
>
Historically, to deploy to AWS, you had to generate a permanent AWS IAM Access Key and paste it into GitHub Secrets. If a rogue employee or hacker extracted that key, they owned your entire cloud infrastructure.

**The OIDC Revolution**

- **Identity Federation:** OpenID Connect (OIDC) establishes a mathematical trust relationship between your GitHub repo and your Cloud Provider (AWS/GCP/Azure).
- **No Stored Secrets:** You no longer store any passwords or access keys in GitHub.
- **Short-Lived Tokens:** When the workflow runs, GitHub proves its identity to AWS. AWS dynamically generates a temporary token that expires in 15 minutes. The deployment finishes, the token dies, and the attack vector is completely eliminated.
</Topic>

<Topic 
  id="kubectl-helm-deploy" 
  title="2. Deploying with kubectl & Helm" 
  shortDesc="Applying manifests to your K8s cluster."
>
Once authenticated, the pipeline must instruct the Kubernetes cluster to start using the newly built Docker image.

**The Deployment Process**

- **Context Switching:** The runner uses the cloud credentials to securely connect to the cluster API (e.g., AWS EKS or GCP GKE).
- **Manifest Updates:** Using tools like `kubectl` or `Helm`, the pipeline updates the deployment manifest to point to the new image tag (the Git Commit Hash).
- **Zero Downtime Rollouts:** Kubernetes takes over, spinning up new Pods with the new image, waiting for them to pass Health Checks, and then gracefully terminating the old Pods. Traffic is never dropped.
</Topic>
