## OIDC Authentication

Historically, to deploy to AWS, you had to generate a permanent AWS IAM Access Key and paste it into GitHub Secrets. If those keys were ever leaked, your entire cloud infrastructure was at risk.

### The OIDC Revolution

OpenID Connect (OIDC) allows your GitHub Actions workflows to communicate with Cloud providers without long-lived secrets.


| Feature | Legacy IAM Keys | OIDC Federation |
| --- | --- | --- |
| **Storage** | Stored in GitHub Secrets | No secrets stored |
| **Lifecycle** | Permanent until rotated | Short-lived (15-60 mins) |
| **Trust** | Static credential | Mathematical Trust relationship |
| **Security** | High risk if leaked | Zero trust, auto-expiring |


- **Identity Federation:** OIDC establishes a trust relationship between your GitHub repo and your Cloud Provider (AWS/GCP/Azure).
- **Short-Lived Tokens:** When the workflow runs, GitHub proves its identity to AWS. AWS dynamically generates a temporary token.


> [!info] Why OIDC?
> Most security breaches happen due to leaked "long-lived" credentials. OIDC eliminates this entire class of vulnerability by using **federated identities** that exist only for the duration of the deployment.







## Deploying with kubectl & Helm

Once authenticated, the pipeline must instruct the Kubernetes cluster to start using the newly built Docker image.

### The Deployment Process

- **Context Switching:** The runner uses the cloud credentials to securely connect to the cluster API (e.g., AWS EKS or GCP GKE).
- **Manifest Updates:** Using tools like `kubectl` or `Helm`, the pipeline updates the deployment manifest to point to the new image tag (the Git Commit Hash).

### Rollout Strategies


| Strategy | Logic | Zero Downtime? |
| --- | --- | --- |
| **Rolling Update** | Replace Pods one-by-one | ✅ Yes |
| **Blue/Green** | Switch traffic to new cluster | ✅ Yes |
| **Canary** | Route 5% of traffic to new image | ✅ Yes |



> [!tip] Self-Healing
> Kubernetes is "declarative." You don't tell it to "start a server"; you tell it "I want 3 replicas of version X." If one of those Pods crashes, K8s automatically restarts it to match your desired state.
