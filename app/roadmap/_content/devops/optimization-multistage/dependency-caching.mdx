---
title: "Configuring Dependency Caching"
shortDesc: "Slashing build times from minutes to seconds."
---

A fresh GitHub Runner starts completely empty. If your Python project requires `numpy` and `pandas`, the runner will waste 2 minutes downloading them from the internet on every single push.

**The Caching Strategy**

- **How it works:** Using the `actions/cache` step, you tell GitHub to zip up your `~/.cache/pip` folder at the end of a successful run and save it to an internal server.
- **Cache Keys:** The cache is saved under a unique key based on the hash of your `requirements.txt`. If your requirements don't change, the key matches.
- **The Restoration:** On the next workflow run, GitHub instantly injects the zipped folder back into the runner. The `pip install` command finishes in 2 seconds instead of 2 minutes.
