---
title: "Environment Variables & Secrets"
shortDesc: "Safely handling API keys and passwords."
---

Hardcoding database passwords or AWS keys into your source code is the fastest way to get your company hacked. Pipelines need a way to access credentials safely.

**Secure Configuration**

- **GitHub Secrets:** A secure vault in your repository settings. You store the actual password here, and reference it in your code using `${{ secrets.DB_PASSWORD }}`.
- **Log Masking:** If your script accidentally tries to print a secret to the console (`echo $DB_PASSWORD`), GitHub intercepts it and prints `***` instead, preventing leaks in the public logs.
- **Environment Variables (`env`):** Used for non-sensitive data (like `NODE_ENV=production` or `LOG_LEVEL=debug`). You can set them at the Workflow level, Job level, or Step level depending on scope.
