<Topic 
  id="serverful-vps" 
  title="1. Serverful (VPS / Bare Metal)" 
  shortDesc="Raw virtual machines where you control the OS, runtime, and security."
>
Virtual Private Servers (VPS) or Infrastructure as a Service (IaaS) gives you a raw virtual machine (like AWS EC2 or a DigitalOcean Droplet). You are handed a Linux terminal and full root access.

**The Concept**

- **Full Control:** You choose the OS, install the runtime, manage security patches, and configure the firewalls.
- **Always On:** You pay a fixed monthly rate 24/7, regardless of whether you have 0 users or 10,000 users.

**When to use it**

- **Predictable Workloads:** If you have constant, heavy traffic, a VPS is significantly cheaper per compute-hour than Serverless or PaaS.
- **Custom Dependencies:** You need to install low-level C++ libraries, custom network drivers, or specialized monitoring daemons.
- **Legacy Systems:** Older monoliths that aren't containerized often require a traditional server environment.

**When NOT to use it**

- **Small Teams:** If you don't have a dedicated DevOps engineer, maintaining security patches and configuring Load Balancers manually is a massive time sink.
- **Unpredictable Traffic:** You either over-provision (wasting money on idle servers) or under-provision (your site crashes during a traffic spike).
</Topic>

<Topic 
  id="paas-platforms" 
  title="2. PaaS (The \"Sweet Spot\")" 
  shortDesc="Platform as a Service. Bring your code, and the cloud handles the infrastructure."
>
Platform as a Service (PaaS) represents the "Sweet Spot" for most modern development teams (e.g., Heroku, Render, Vercel, AWS AppRunner).

**The Concept**

- **Bring Your Own Code:** You simply connect your GitHub repo or push a Docker container. The platform handles the OS, load balancing, SSL certificates, and zero-downtime deployments.
- **The Sweet Spot:** It abstracts away the headache of Linux administration while still keeping your application running 24/7 like a normal server.

**When to use it**

- **Startups & Small Teams:** When your primary goal is shipping product features fast, not managing infrastructure.
- **Standard Architectures:** Perfect for standard REST APIs, SSR frameworks (Next.js), and typical background worker queues.
- **Easy Scaling:** Need more power? Just drag a slider in the UI to add more instances behind their managed load balancer.

**When NOT to use it**

- **Massive Scale (Cost):** The convenience comes at a premium. At massive enterprise scale, PaaS compute costs can be 2x to 5x higher than managing your own raw VPS instances.
- **Extreme Customization:** You cannot access the underlying host OS. If you need weird network routing or custom kernel modules, PaaS will block you.
</Topic>

<Topic 
  id="serverless-faas" 
  title="3. Serverless (FaaS)" 
  shortDesc="Ephemeral, event-driven compute scaling from zero to thousands instantly."
>
Serverless (Function as a Service / FaaS) fundamentally changes how compute is billed and executed (e.g., AWS Lambda, Google Cloud Functions).

**The Concept**

- **Event-Driven:** Your code only runs in response to a trigger (an HTTP request, a file uploaded to a bucket, or a cron schedule).
- **Pay Per Millisecond:** You are billed exactly for the execution time. If no one visits your site, your bill is literally $0.00.
- **Infinite Scaling:** The cloud provider spins up thousands of parallel instances instantly to handle sudden spikes.

**When to use it**

- **Unpredictable/Bursty Traffic:** E-commerce sites during Black Friday, or ticket sales. It scales from 0 to 10,000 requests per second instantly without crashing.
- **Glue Code & Background Jobs:** Perfect for tasks like "Resize this image when it's uploaded" or "Send an email when a record hits the queue."

**When NOT to use it**

- **Constant, High Traffic:** If a function runs constantly 24/7, Serverless becomes significantly more expensive than a standard VPS.
- **Long-Running Processes:** Cloud functions typically have a hard timeout limit (e.g., 15 minutes). You cannot run a 3-hour video encoding job on a single Lambda.
- **Low Latency / Real-Time:** Suffer from "Cold Starts." If a function hasn't run recently, it takes a few seconds to boot up the container, making it poor for real-time multiplayer gaming.
</Topic>
