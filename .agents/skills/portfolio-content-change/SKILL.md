# Change portfolio content

Read `AGENTS.md` and the source content for the affected route. Use
[portfolio-change](../portfolio-change/SKILL.md) for substantial task phases and
records. Identify the current claim, the user's requested wording change and
where that claim appears before editing.

Write concise, professional, human-sounding copy. Explain what a project is and
what problem it addresses; keep project status, technology and outcomes accurate.
Avoid service promises, inflated results, invented users or metrics, and repeated
`I` phrasing. Preserve claims unless the user approves a change to them. If a
technical assertion cannot be verified from project material, flag it instead
of polishing it into a stronger claim.

For roadmap prose, retain technical meaning, heading hierarchy, links and
searchable terms. Check rendered MDX and line lengths where the change affects
readability. If the user asks for proposed copy before editing, provide the
proposal and stop before modifying content.
